# ADR 0006 — Sidebar group labels are patched in route middleware, not declared in the sidebar config

**Status:** Accepted
**Date:** 2026-07-30

## Context

An autogenerated Starlight group takes its directory name verbatim, so the
Mirror's `channels/` and `deployment/` render lowercase. Fixing that is the
second of the three requirements `argus` ADR 0022 places on this repository, and
both it and ADR 0003 word the requirement the same way: **relabel the sidebar
groups in `astro.config.mjs`**. The research in `argus` under
`docs/research/starlight-content-conventions.md` §3c reaches the same place — it
lists exactly two mechanisms, both in the site's config, and recommends assuming
the site declares explicit groups.

Implementing it surfaced a cost that none of the three had measured.

Verified against the installed Starlight 0.41.5:

- There is no per-directory label option. `autogenerate` accepts only
  `{ directory, collapsed, attrs }`, and a `label` alongside it is a hard error
  left over from the 0.39.0 migration. `groupFromDir` sets `label: dirName`.
- There is no way to autogenerate one level and hand-declare the next.
  `autogenerate` recurses to the bottom; the `depth` option that would stop it is
  a commented-out TODO in the sidebar schema.

So "declare the labels in `astro.config.mjs`" means, unavoidably, **enumerating
the Guide's top-level pages in this repository**. That has two costs, and the
second is worse than the lowercase labels it buys:

1. A page added upstream stays out of the sidebar until somebody edits this
   repository — the inverse of what the Guide's `sidebar.order` is for.
2. A page **deleted** upstream fails the build. Measured:
   `AstroUserError: The slug "guide/a-page-the-sync-deleted" specified in the
   Starlight sidebar config does not exist.` The Sync deletes as well as adds
   (ADR 0002), so the first upstream deletion would take the whole site's build
   down instead of removing one page.

Renaming the directories to `Channels/` and `Deployment/` — the research's other
mechanism — is not available either: the Mirror is written only by the Sync,
which replaces it wholesale, so the rename would survive until the next run.

## Decision

**Keep the sidebar fully autogenerated, and relabel the generated groups in a
Starlight route middleware.**

`astro.config.mjs` declares `sidebar: [{ autogenerate: { directory: 'guide' } }]`
and points `routeMiddleware` at `src/route-middleware.ts`, which walks the
generated tree and replaces group labels from a map. The map is keyed by the
label Starlight generated, which for an autogenerated group is the directory
name.

Ordering and membership therefore stay entirely with the Guide's own frontmatter,
which is what ADR 0003 promised, and the labels are still owned by this
repository, which is what `argus` ADR 0022 required.

## Consequences

- **This contradicts ADR 0003's last consequence and `argus` ADR 0022's second
  requirement as literally worded** — the labels are not in `astro.config.mjs`.
  Both are met in substance: the labels are owned here, in code this repository
  controls, reached from `astro.config.mjs`. Only the file changed. Recorded
  rather than quietly diverged.
- **A new upstream directory renders lowercase** until an entry is added to the
  map. Cosmetic, visible on the page, and it does not fail the build — but
  nothing warns either, so it is found by looking.
- **The map keys on undocumented behaviour.** That a group's label equals its
  directory name is source-derived, not a documented contract; Starlight PR #2688
  already changed it once, in the other direction, when labels stopped being
  sluggified. A future release that title-cased or sluggified them would leave the
  map silently unmatched — the failure is a wrong label, not an error.
- **No fork and no patch.** Route middleware is a documented Starlight extension
  point, so this costs nothing at upgrade time beyond the type of the route data.

## Alternatives considered

- **Explicit groups in `astro.config.mjs`**, the researched recommendation.
  Rejected for the two costs above — the build-breaking one especially, because it
  converts the Sync's most valuable property, that it deletes, into an outage.
- **Renaming the Mirror's directories** so their names read as labels. Rejected:
  the Sync would undo it, and the Mirror is read-only by convention (ADR 0001).
- **Asking upstream for a frontmatter field.** Rejected as not upstream's to
  give: Starlight reads no frontmatter at all for group labels, so the change
  would have to land in Starlight rather than in `argusappsec/argus`.
