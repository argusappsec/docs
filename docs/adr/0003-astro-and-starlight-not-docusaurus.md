# ADR 0003 — Astro and Starlight, not Docusaurus

**Status:** Accepted
**Date:** 2026-07-30

## Context

Docusaurus is the obvious choice for a documentation site and was recommended
first here, for a specific reason: at the time the Guide had **no frontmatter at
all**, and Docusaurus infers a page title from the first `# H1` while Starlight
requires `title` in frontmatter. Under ADR 0001 the Mirror is read-only, so
"the Mirror must build exactly as it arrives" was a hard requirement, and only
one of the two candidates met it.

That requirement then dissolved: `argus` ADR 0022 made `docs/guide/` a
self-contained Starlight source, with `title`, `description` and `sidebar.order`
on every page and body `<h1>`s removed. Two of the three reasons for Docusaurus
were reasons about content that no longer holds, and the third — versioning
built in — is a benefit only cashed at 1.0.

## Decision

**Astro with Starlight, styled with Tailwind.**

- **Tailwind is a first-class Astro integration.** Under Docusaurus it runs
  through PostCSS on a Webpack build, with preflight disabled so it stops
  fighting Infima — a fight paid for twice, once to set up and once per upgrade.
- **Search works with no setup.** Starlight ships Pagefind: a local index, no
  external service, no application to file. A Docusaurus MVP ships with no
  search at all unless Algolia DocSearch is applied for or a community plugin is
  bolted on. On a documentation site search is not a frill.
- **The content root is `src/content/docs/`,** so the repository-root `docs/`
  stays free for Agent docs. Docusaurus wants `docs/` at the root, which would
  have collided with the skill configuration already living there.
- **The Landing is a plain Astro page** with zero JavaScript by default, rather
  than a React page inside a documentation framework.

## Consequences

- **Versioning at 1.0 is a community plugin (`starlight-versions`), not core.**
  Nothing is needed pre-1.0 either way, so the cost is deferred and known.
- **Smaller ecosystem than Docusaurus.** Accepted.
- **The Mirror's mount path is not configurable.** Per the research recorded in
  `argus` under `docs/research/starlight-content-conventions.md` (verified
  against Starlight 0.41.5 / Astro 7.1.6), `docsLoader()` hard-codes its `base`
  to `<srcDir>/content/docs` and does not expose it. The Mirror must physically
  sit at `src/content/docs/guide/`, which is also what fixes the URL prefix at
  `/guide/`.
- **`/guide/`, not `/docs/`.** The conventional prefix was preferred at first,
  but it would have put the Mirror at `src/content/docs/docs/` and left three
  different things in this repository called "docs". `/guide/` is also the word
  the project already uses for this content, and the Guide's own internal links
  are written against it.
- **Sidebar ordering is owned upstream.** It comes from `sidebar.order` in
  frontmatter, so a new Guide page appears on the site in the right place with
  no edit here. Group *labels* must still be set in `astro.config.mjs`: an
  autogenerated group takes the directory name verbatim, which would render
  `channels/` and `deployment/` lowercase.
